## 🔧 **6. SCANNER THRESHOLD IMPROVEMENT NOTES:**

### **Issues Identified for Future Refinement:**

#### **Issue 1: Exponential Complexity Formula Too Aggressive**

**Current Formula Expectation:**
```python
expected_complexity = previous_district_complexity × exponential_factor
# HAVSDOMINANSEN expected: ≥2.452 (but got 1.686)
# VIRTUALITETSHELGEDOMMEN expected: ≥2.452 (but got 2.155)
```

**Problem:**
- Formula expects EVERY district to exponentially increase complexity
- Real-world: Quality-focused development creates stable, maintainable complexity
- Two consecutive districts (HAVSDOMINANSEN, VIRTUALITETSHELGEDOMMEN) both "failed" this threshold

**Proposed Improvement:**
```python
# Option 1: Adjust exponential factor (lower expectations)
expected_complexity = previous_district_complexity × 1.05  # Instead of 1.10+

# Option 2: Use rolling average instead of exponential
expected_complexity = average_of_last_3_districts × 0.95  # Within 5% of average

# Option 3: Complexity ceiling (prevent runaway expectations)
expected_complexity = min(previous_district_complexity × 1.10, 2.500)  # Cap at 2.5
```

#### **Issue 2: Quality vs. Quantity Balance**

**Observation:**
- VIRTUALITETSHELGEDOMMEN has MOST documentation (2,911 lines)
- But complexity score (2.155) is lower than SKYSKRAPEREN (2.335 with 2,070 lines)
- This suggests quality/quantity weighting needs tuning

**Proposed Improvement:**
```python
# Current formula (assumed):
complexity = (num_specialists × avg_quality) + (pathways_quality × 1.5) + (state_quality × 1.2)

# Proposed formula:
complexity = (
    (num_specialists × avg_quality × specialist_weight) +
    (pathways_quality × pathways_weight) +
    (state_quality × state_weight) +
    (total_lines / 1000 × documentation_weight)  # Reward documentation volume
)

# Example weights:
specialist_weight = 0.8
pathways_weight = 1.5
state_weight = 1.2
documentation_weight = 0.3  # New: Reward high documentation
```

#### **Issue 3: Precedent Inconsistency**

**Problem:**
- HAVSDOMINANSEN got ⚠️ BELOW_THRESHOLD but was approved
- Creates precedent that threshold warnings are non-blocking
- But scanner still reports them as warnings (confusing)

**Proposed Improvement:**
```python
# Option 1: Lower threshold to match precedent
if actual_complexity >= expected_complexity × 0.70:  # Within 30% is acceptable
    status = "✅ PASS"
else:
    status = "⚠️ BELOW_THRESHOLD"

# Option 2: Add "tolerance zone"
if actual_complexity >= expected_complexity:
    status = "✅ EXCEEDS"
elif actual_complexity >= expected_complexity × 0.85:
    status = "✅ ACCEPTABLE (within tolerance)"
else:
    status = "⚠️ BELOW_THRESHOLD"
```
